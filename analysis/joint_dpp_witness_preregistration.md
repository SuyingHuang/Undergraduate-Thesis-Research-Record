# Joint DPP + 75% witness：重新筛查预注册

状态：在查看 witness 版本的仿真效果输出之前冻结。修改动机和旧版本负结果见
[`20260912_joint_dpp_c1_results.md`](20260912_joint_dpp_c1_results.md)。

## 固定修改

唯一算法修改是在原 `joint_dpp-g9` 旧频率候选集合中加入
`budgeted-75%` 解析反解得到的聚合频率。75% 在阶段 A 后已经冻结，并非根据 C1
重新选择。网格、目标权重、上层候选、训练参数和其余解析转折点不变。

新标识为 `joint_dpp-g9-w75`。它应满足两个可测试性质：

1. witness 频率产生的处理量、能耗和占用时间与独立 75% 策略完全一致；
2. 对同一状态和卸载动作，联合搜索的实现目标不高于 75% witness。

这只是单步实现目标的支配性质，不保证跨帧 PAoI、队列或能耗必然优于 75%。

## W0：执行复核

## W1：新种子机制筛查

- 512 帧；负载 10、12、16 Mbit；标准差 3 Mbit；`J=10`；
- 环境种子：67867967、86028121；
- 策略种子：2029、3037；
- 处理：legacy、`budgeted-75%`、`joint_dpp-g9-w75`；
- 统计后半 256 帧；环境是独立重复，策略种子嵌套于环境；
- 保存旧聚合频率、旧/新能耗、旧/新服务、占用时间和现有全部审计轨迹。

进入独立确认的必要条件固定为：

1. 36/36 运行完整且没有物理记账异常；
2. joint-w75 在每个负载的两个环境级均值上都不得同时劣化 PAoI、队列和能耗；
3. joint-w75 相对 75% 至少在一个负载上改善 PAoI 或物理队列，且另一个指标的
   相对劣化不超过 1%；
4. 若不满足，不再增加固定 witness、网格点或事后容差，终止该联合搜索路线。

W1 命令：

```bash
python analysis/run_old_bs_generalization.py \
  --frames 512 --loads-mbit 10 12 16 --task-std-mbit 3 \
  --users-per-bs 10 --scenario-seeds 67867967 86028121 \
  --policy-seeds 2029 3037 --budget-fractions 0.75 \
  --include-joint-dpp --joint-dpp-grid-points 9 \
  --workers 8 --device cpu
```

即使 W1 通过，也必须另写使用全新环境种子的 2048 帧确认方案后才能启动长跑；
W1 本身不提供最终结论。
