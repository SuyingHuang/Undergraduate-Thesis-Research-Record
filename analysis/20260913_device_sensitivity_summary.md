# 设备敏感性受控 A/B（2026-09-13）

## 目的

正式实验会在宿主机 GPU 上运行，而 2026-09-13 的全部 CPU pilot 都是在无 GPU 的
受限沙箱中完成的。如果同一提交、同一环境种子在不同设备上给出不同数字，那么
（a）设备必须作为实验环境的一部分记录，（b）任何比较都不能混用 CPU 与 GPU 运行。
本记录用一次受控 A/B 定量回答这个问题，并顺带排除线程设置的混淆。

## 设计

唯一受控变量是 `LDA_DEVICE`，其余全部相同：

| 项 | GPU 臂 | CPU 臂 |
| --- | --- | --- |
| 结果目录 | `results/sweep/20260913_220855_456859_Exp1_J` | `results/sweep/20260913_225817_101821_Exp1_J` |
| 入口 | `scripts/ldactl sweep` | `scripts/ldactl sweep` |
| 提交 | `6cd162f`（`git_worktree_dirty=false`） | `6cd162f`（`git_worktree_dirty=false`） |
| `dnn_device_request` | `auto` → `cuda:0` | `cpu` |
| 实验 / 帧数 / 种子 / worker | `Exp1_J` / 512 / 42,123 / 10 | 同左 |
| 线程环境 | `run_linux.sh` 默认 `OMP=MKL=OPENBLAS=NUMEXPR=1` | 同左 |
| `task_retries` | 1（未触发） | 1（未触发） |

两臂各 48 个任务，全部成功，场景哈希逐 (参数, 种子) 一致。

线程环境是刻意控住的：早先一次 CPU pilot 直接调用 `run_sweeps.py`，绕过了
`run_linux.sh` 的线程限制，导致启发式出现 0.1%–0.5% 的差异。那次差异是混淆，
不是设备效应；下文的干净结果证实了这一点。

## 结果

末半程固定窗口的时延惩罚，逐种子对比：

| 算法 | 逐帧完全一致 | 最大相对差 |
| --- | ---: | ---: |
| COB | 12/12 | 0.000% |
| MTD | 12/12 | 0.000% |
| LDA1 | 10/12 | 1.538% |
| LDA2 (AC) | 7/12 | 9.356% |

**启发式在控制线程后逐帧完全一致**，说明它们对设备不敏感；学习算法则不然。

## 机制

分歧不是指标噪声，而是**决策翻转导致的轨迹分叉**：

| 算法 | J | 种子 | `Cost` 首个差异帧 | `Loss` 首个差异帧 |
| --- | ---: | ---: | ---: | ---: |
| AC | 14 | 123 | 30 | 260 |
| AC | 8 | 42 | 39 | 260 |
| LDA | 10 | 123 | 41 | 270 |
| LDA | 12 | 123 | 49 | 270 |
| （其余 41 个运行） | | | 无差异 | 260–270 |

关键观察：

1. **所有分歧都发生在第 30–49 帧，而首次训练更新在第 260–270 帧之后。** 也就是说
   分叉发生在**没有任何梯度更新**的阶段，因此不是训练数值差异造成的。
2. 同一比较中，信道状态（`R_bs_max/min`、`R_sat_max/min`）与探索窗口
   （`delta_t` 全部 512 点）**逐点相同**，排除了环境 RNG 与自适应窗口走样。
3. `Loss` 恰在首次训练帧出现差异，与第 1 点互为佐证。

因此机制是：**设备相关的 DNN 前向浮点舍入在近似并列的候选上翻转了选择**。策略是
决策量化的，一旦早期某一帧的动作翻转，后续轨迹按混沌方式分叉，256 帧平均值随
之移动几个百分点。这也解释了为什么多数运行完全一致、少数运行差到近 10%——翻转
是偶发的，但一旦发生后果不可忽略。

## 结论与操作规则

1. **设备是实验环境的一部分。** 同一提交、同一环境种子、不同设备**不保证**相同
   数字。论文与图注必须记录设备，不能把 CPU pilot 与 GPU 正式运行当作同一条件。
2. **同一次比较内禁止混用设备。** manifest 的 `runtime.cuda_available`、
   `runtime.cuda_health` 与任务日志的 `[DNN] device=` 足以事后检出混用。
3. **启发式跨设备可复现**，因此 COB/MTD 可以安全地跨设备引用。
4. 这不是缺陷，而是决策量化策略的固有性质；不应对数值差异做“修 bug”式的处理，
   而应在威胁有效性一节披露。

## 边界

- 512 帧、2 个环境种子、单机单次对照，不构成对更长时间域或其它硬件的普遍结论。
- 本实验只分离了“CPU vs GPU”这一个设备维度；不同 GPU 型号、不同 CUDA 版本之间的
  差异未测。
- `device_count=1`：本次 A/B 的 GPU 臂只使用了 `cuda:0`（宿主内核注册 2 张 4090，
   但 CUDA 只报告 1 张），第二张卡是否可用尚未确认。这不影响数值结论，因为它对
   两臂是同一条件之外的常量，但会影响正式运行的吞吐画像。
